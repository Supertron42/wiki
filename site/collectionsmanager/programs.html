Programs and shared libraries

Save tool setups once, install them deliberately and share portable recipes with other users.

Add a program

  1. Choose Add program. Pick its Nexus or external source.
  2. Review the downloaded or selected archive, its wrapper folder and the files to include. You can explicitly leave archive setup for later.
  3. Choose its installation location, relative executable path and launch mode.
  4. Review and save the definition. Add program saves the setup; choose Get afterward to install. Cancel creates no entry.

Configure an existing entry

Select a row to open its setup pane, even before it is installed. Save setup changes the recipe. Get, Reinstall and Uninstall are separate actions. Browse can attach a local archive; a changed source needs a fresh archive/layout review. Tools with web installers still need their manual installation steps.

Launch through MO2

Through MO2 queues executable registration and may require restarting MO2. For an installed tool, right-click Add to MO2 launcher to retry without reinstalling. Missing executables or launcher errors remain Needs attention. Direct and No launcher are separate launch choices; saving a setup does not run the program.

Share a program library

  1. Use Programs > More > Export program library and choose the entries to share.
  2. Share the JSON configuration file. It contains source and layout/launcher recipes, not programs, downloaded archives, API keys or personal installation paths.
  3. Import program library previews entries before saving. Conflicting IDs start unchecked. Choose Keep both or explicitly Replace selected program setups where supported.
  4. Import saves configuration only. Use Get to install afterward. A game-folder tool cannot become two independent installations in the same game folder.

Limits and version choices

Libraries support up to 500 program definitions in a 16 MB file; this is not a collection-mod limit. MO2’s existing arbitrary command-line arguments and global appearance preferences are not exported as library fields. Different-game imports require acknowledgment.

Runtime Swapper is listed below SKSE64 and asks for an explicit source/target package. Free accounts keep manual website downloads. A recognized Swapper installation can let CM compare SKSE with the intended launch runtime, after checking its installed files and the actual game executable against the package’s recorded hashes. Missing, edited, unsupported or ambiguous evidence is not accepted as a match.

When a collection requests both, Swapper is set up before SKSE; an already installed SKSE setup is rechecked too. These are installation checks: real swapping, the author’s release binaries and actual game launching are not validated by this work. Automatic requirements management and revision isolation remain unfinished.

Uninstall and ownership

Uninstall removes only unchanged files CM recorded as its own. Shared, pre-existing, edited and untracked files are retained. An existing folder or linked executable can be detected without CM claiming ownership of it.
