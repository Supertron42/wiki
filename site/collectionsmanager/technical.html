How Collections Manager works

A closer look at collection definitions, installation checks, portable setups and the boundaries of supported tools.

MO2 interface, background processing

Python and PyQt6 provide the interface and MO2 integration. The matching Rust engine handles much of the downloading, archive processing, hashing and installation work. Keep the complete matching package together when updating.

The native engine, plugin and FOMOD helper work as a set. A configured row or familiar folder name is not proof that the requested tool or archive is installed.

What a collection carries

An MO2 Collection ZIP can carry mod sources, order, enabled state, FOMOD choices, instructions, bundled content, selected settings changes and program recipes. Referenced mods download from their sources; only explicitly bundled files travel inside the ZIP.

Explicitly selected Overwrite files are embedded as a named included MO2 mod. The recipient’s Overwrite folder stays unchanged. Author profiles retain local selections, while imported ZIPs can reuse their embedded files without the author’s folder.

Program libraries carry portable configurations rather than installed programs, account keys or personal installed paths. Importing a recipe does not download, install or execute it.

Review and installation are separate steps

Saved FOMOD choices are checked against the exact archive and available installer options. A configured badge describes saved metadata; actual installation checks the archive again.

Stop ends pending work while an active installer finishes. Skipped, failed and unfinished items remain distinct from successfully installed items. Use Needs attention and Fix Failed to resolve the next required action.

Premium enables the supported automatic Nexus download flow. Free accounts retain Nexus's manual website steps and can select local archives.

Revisions and shared files

Revision review compares added, removed, changed and unchanged items before loading a new definition. Loading a revision for review does not install anything. Removed mods remain installed; optional exclusions do not uninstall their files.

MO2 profiles share installed mod folders. A game-root program can affect every profile using that game installation. A collection revision does not create an isolated copy of the installed setup, and profile order/settings snapshots do not back up every mod file.

Game and tool support

Collection and source selection follow the game managed by the active MO2 instance. A tool's availability, archive layout and runtime requirements must be checked for that game; collection support does not imply that every included tool supports every MO2 game.

The optional record conflict resolver currently reads Skyrim Special Edition plugin files. It previews supported container, leveled-list and selected NPC changes. It does not combine scripts, face appearance or FaceGen assets, or reproduce changes made by a running SKSE plugin.

The optional Include empty nested lists setting is on by default. It includes qualified unchanged empty child overrides reachable from an exported leveled list, including through unchanged nonempty children. Changed-to-empty lists still export when the option is off. Unrelated empty lists stay out of the patch, and invalid branches appear in Skipped.

Eligible existing-record overrides can export as an ESL-flagged ESP when the detected runtime supports light plugins; older or unrecognized runtimes retain a full ESP. CM does not compact or renumber FormIDs. Review the saved result in xEdit and test it in the intended game setup.

Maintenance and tool guidance

Recovery and ownership

Supported program operations record ownership of installed files. Uninstall retains shared, pre-existing, changed and untracked files. CM stages supported changes and attempts recovery after an ordinary failure or cancellation; keep independent backups for the files you need.

Some root tools, runtime-specific packages and launchers require additional review. An existing folder or executable alone does not establish a verified installation, and setup checks do not validate gameplay.

About the interface views

The overview’s interface images render the actual Collections Manager UI offscreen, using cached collection definitions and saved program recipes. Mod names, versions and file identities come from those saved records. Program setup shows saved download sources, destinations and launcher choices alongside the toolkit’s built-in definitions. Display paths are sanitized; account credentials are omitted.

The images show an isolated review session. Install entries remain pending and program installation status is not checked. The Create view is a draft prepared from saved collection metadata. No live account check, download, installation, export or program launch was performed to create these views; they do not report the current state of a running MO2 instance.
