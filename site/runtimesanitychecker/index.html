Runtime Sanity Checker

Look for specific suspicious perk, magic-effect, AI-package, quest-alias and attached-script data when Skyrim starts. The scanner writes findings so you can investigate the responsible records.

Get started

  1. Choose the plugin download for your exact Skyrim version and store edition. Use the matching SKSE and Address Library required by that download.
  2. Install the complete package with your mod manager, including its Data assets. Back up personal settings before replacing an older mod folder.
  3. Start Skyrim through SKSE. For these settings, restart Skyrim after saving changes unless the guide describes a separate reload control.

Settings

Use Data/SKSE/Plugins/RuntimeSanityChecker.json or the optional settings menu. Individual checks, detailed logging and report output can be enabled separately.

SettingWhat it changes
Perks and magic effectsCheck whether effect data matches the expected type.
AI packages and quest aliasesLook for missing or unrecognized targets and references.
Attached scriptsReport initialization or property references that do not resolve.
ReportsOpen the HTML report in the SKSE log folder or Data/PrismaUI/views/RuntimeSanityChecker/report.html.

Limits and troubleshooting

  • The scanner reports; it does not repair records or create a patch.
  • A finding is a reason to investigate, not proof that the record caused a particular crash. A clean scan does not certify the entire mod list.
  • It still needs a matching game/runtime build. Read-only scanning is not a universal compatibility or save-safety guarantee.
